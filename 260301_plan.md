## 2. V4의 문제점과 V5의 설계 동기

### V4 사양 (3.85M params)

```
 Transformer Decoder: 4 layers, d_model=128, FFN=512, 8 heads
 Decoder 파라미터: ~2.1M (전체의 55%)
 z_global: 32-dim, token 생성 시 1회 concat
 A2A attention: 순수 learned (물리적 관계 없음)
 학습: Teacher Forcing only (GT state 사용)
```

### 진단된 5가지 구조적 문제

```
 ┌─────────────────────────────────────────────────────────────────────┐
 │ Problem 1: z_global Posterior Collapse                             │
 │                                                                    │
 │ 원인: z_global이 token 생성 시 1회 concat → 4 layer 통과하면서 희석  │
 │       decoder capacity가 충분하여 z 없이도 trajectory 생성 가능      │
 │                                                                    │
 │ 증상: posterior가 prior로 수렴 (KL → 0), z가 무의미해짐              │
 │                                                                    │
 │ V5 해결:                                                            │
 │   (1) AdaLN → z_global 매 layer 매 norm에서 재주입                  │
 │   (2) Decoder 축소 → capacity 제한으로 z 의존도 강제                │
 │   (3) z_aux decoder → z_global 정보 보존 강제 (aux loss)            │
 ├─────────────────────────────────────────────────────────────────────┤
 │ Problem 2: 과도한 Decoder Capacity                                  │
 │                                                                    │
 │ 원인: 4 layers × FFN 512 = ~2.1M params                           │
 │       7,800 시나리오 대비 과다한 capacity                             │
 │                                                                    │
 │ V5 해결: 2 layers × FFN 256 = ~1.1M params (48% 감소)              │
 ├─────────────────────────────────────────────────────────────────────┤
 │ Problem 3: A2A에 물리적 정보 없음                                   │
 │                                                                    │
 │ 원인: agent 간 attention이 순수 learned embedding 기반               │
 │       거리/속도/TTC 등 물리량을 반영하는 inductive bias 없음         │
 │                                                                    │
 │ V5 해결: 8개 pairwise physical feature → MLP → additive bias       │
 ├─────────────────────────────────────────────────────────────────────┤
 │ Problem 4: Teacher Forcing → Autoregressive Gap                    │
 │                                                                    │
 │ 원인: 학습은 GT state (parallel), 추론은 자기 예측 (sequential)     │
 │       분포 불일치 → AR 시 오차 누적                                  │
 │                                                                    │
 │ V5 해결: Action Blending                                            │
 │   α=0(순수 TF) → α=1.0(완전 AR)로 점진 전환                        │
 │   action 수준 내분: a = (1-α)·a_GT + α·â_pred                      │
 ├─────────────────────────────────────────────────────────────────────┤
 │ Problem 5: 학습 상태 불투명                                         │
 │                                                                    │
 │ 원인: z_global, intent, map attn의 건강 상태 모니터링 부재           │
 │       문제 발생 시 원인 파악 불가                                    │
 │                                                                    │
 │ V5 해결: Health Monitoring (TensorBoard)                            │
 │   z norm/std/active_dims, intent entropy/slot_usage,               │
 │   map attn entropy/peak, per-module grad norms                     │
 └─────────────────────────────────────────────────────────────────────┘
```

## 3. 전체 데이터 흐름 (End-to-End)

### Training (Teacher Forcing, α=0)

```
 Input Scene Graph:
   past:       (NA, 4, 6)   ← 4 steps × (x, y, hx, hy, speed, hdot) normalized
   future_gt:  (NA, 12, 6)  ← 12 steps GT
   lw:         (NA, 2)      ← (length, width) normalized
   sem:        (NA, 4)      ← semantic class one-hot
   edge_index: (2, E)       ← GCN connectivity
   ptr:        (B+1,)       ← batch pointer (ego = ptr[b])
   map raster: (NA, 4, 256, 256) ← drivable, solid, dashed, centerline

 Step 1: Map Encoding
   map raster → Conv1-3 (early) → map_tokens (NA, 841, 64)
                                → Conv4-6 (late) → flatten → Linear → map_feat (NA, 64)

 Step 2: Prior (past only)
   past → per-step [MLP + GCN] → GRU → past_context (NA, 64)
   [past_context, map_feat, sem] → MLP → prior_μ, prior_σ² (NA, 32)

 Step 3: Posterior (past + future)
   past → GRU context
   future → per-step [MLP + GCN] → PE + TF Encoder → future_context (NA, 64)
   [past_ctx, future_ctx, map_feat, sem] → MLP → post_μ, post_σ² (NA, 32)

 Step 4: z_global sampling
   z = post_μ + ε·√(post_σ²), ε ~ N(0,1)   (reparameterization)

 Step 5: z_aux (auxiliary decoder)
   z_ego(32) + step_embed(32) → MLP(64→128→128→2) → aux_pred (N_ego, 12, 2)

 Step 6: Decoder
   all_states = [past(4), future_gt(12)]   ← 16 steps GT
   per-step GCN → gcn_feats (NA, 16, 64)
   token = Linear([gcn(64), z(32), lw(2), sem(4)]) + temporal_PE → (1, 16, NA, 128)

   map_recrop: 각 step GT 위치 기준 map 재생성 (256×256 → CNN → 841 tokens)

   Layer 0: A2T → A2A(+rel_bias) → A2Z(z_cross_attn) → A2S(map_cross_attn) → FFN
            [All norms: AdaLN(z_global)]
            → aux outputs: sur_pred, ego_pred, map_attn_weights

   Intent Codebook (between Layer 0-1):
            ego tokens → MLP → Gumbel-Softmax(K=9) → z_local(32)
            [ego_token, z_local] → Linear(160→128) → replace ego tokens

   Layer 1: A2T → A2A(+rel_bias) → A2Z → A2S → FFN

 Step 7: Output (shifted: PE[3:15] → future step[0:11])
   ego_tokens → ego_output_head → (acc, yaw_rate)
   sur_tokens → sur_output_head → (acc, yaw_rate)

 Step 8: Bicycle Model
   for t in 0..11:
     prev_state = GT_state[t-1]  (or last_past if t=0)
     s_t = bicycle(prev_state, acc_t, yaw_t, veh_length)
   → traj_out (NA, 12, 4)
```

### Training (Blended, α>0)

```
 차이점: Step 6-8이 AR loop로 변경

 for t in 0..11:
   accumulated_tokens = [past(4) + predicted(0..t-1)]
   Transformer(causal_mask) → last token → output_head → â_pred

   a_applied = (1-α)·a_GT[t] + α·â_pred     ← action 수준 blending
   s_t = bicycle(prev_blended_state, a_applied, veh_length)

   new_token = GCN(s_t) + z + lw + sem → proj + PE → append

 Gradient는 전체 loop를 통해 유지 (no detach)
 α=0이면 TF와 완전 동일, α=1이면 완전 AR
```

### Inference (Autoregressive)

```
 z_global = prior_μ (or sampled from prior)
 동일 AR loop, α=1 (predicted action만 사용)
 no GT action available → 순수 자기 예측으로 생성
```

## 4. Part A — Map Encoder (CNN)

```
 ┌─────────────────────────────────────────────────────────────────────┐
 │ Map Raster Input: (NA, 4, 256, 256)                                │
 │   ch0: drivable_area                                               │
 │   ch1: solid_line (lane boundary)                                  │
 │   ch2: dashed_line (lane separator)                                │
 │   ch3: centerline                                                  │
 │                                                                    │
 │ Crop: ego 중심 77m × 77m, 해상도 0.3m/px                           │
 │       종방향 비대칭: 전방 60m, 후방 17m (bounds: [-17, -38.5, 60, 38.5])│
 └─────────────────────────────────────────────────────────────────────┘

 Early Conv (conv1-3) — map token 생성용
 ┌────────────────────────────────────────────────┐
 │  Conv2d(4→16, k=7, s=2)  + GN(1,16) + ReLU   │  256 → 125
 │  Conv2d(16→32, k=5, s=2) + GN(1,32) + ReLU   │  125 → 61
 │  Conv2d(32→64, k=5, s=2) + GN(1,64) + ReLU   │   61 → 29
 └────────────────────────────────────────────────┘
  Output: (NA, 64, 29, 29) → flatten → (NA, 841, 64) = map_tokens
  841 tokens × 64 channels, ~2.65m/token 해상도
  Params: 67,472

  Config 토글: conv_stride_list로 해상도 선택 가능
    [2, 2, 2, ...] → 29×29 (2.65m/token) ← 현재 사용
    [2, 2, 1, ...] → 57×57 (1.35m/token)  (3번째 stride만 변경)
    모든 downstream (model, loss, viz)이 map_token_spatial 동적 사용

  RF 좌표 매핑 (Bug Fix — CRITICAL):
    CNN padding=0 → token[0]의 RF center는 pixel 0이 아닌 pixel 15
    token[m] RF center pixel = m × rf_stride + rf_offset
    rf_offset = Σ(k_i-1)/2 × Π(s[:i]) = 15 (kernel [7,5,5])
    rf_stride = Π(s[:3]) = 8 (stride [2,2,2]) or 4 (stride [2,2,1])
    model.py에 self.map_rf_stride, self.map_rf_offset 저장
    이전 코드: token = meters × (pix/total_m) × (grid/pix) → ~3m 오프셋
    수정 후:   token = (pixel - rf_offset) / rf_stride → 정확한 매핑

 Late Conv (conv4-6) — encoder feature 생성용
 ┌────────────────────────────────────────────────┐
 │  Conv2d(64→64, k=3, s=2)   + GN(1,64) + ReLU │  29 → 14
 │  Conv2d(64→128, k=3, s=2)  + GN(1,128)+ ReLU │  14 → 6
 │  Conv2d(128→128, k=3, s=2) + GN(1,128)+ ReLU │   6 → 2
 └────────────────────────────────────────────────┘
  Output: (NA, 128, 2, 2) → flatten(512) → Linear(512→64) = map_feat
  Params: 259,008 + 32,832 = 291,840

 ┌───────────────────────────────────────┐
 │ Map Encoder Total: 359,312 params    │
 │   early (tokens):  67,472            │
 │   late (feature): 259,008            │
 │   feat linear:     32,832            │
 └───────────────────────────────────────┘
```

### Map Recrop (map_recrop=True)

```
 문제: decoder에서 12 step 미래를 예측하면, agent가 최대 ~22m 이동 가능
       초기 crop 기준 map tokens는 이동 후 위치에서 부정확

 해결: 각 decode step에서 해당 위치 기준으로 map raster를 재생성
       position → unnormalize → get_map_crop → Conv1-3 → new tokens

 장점: map attn soft label 좌표계와 자연스럽게 일치
 비용: step당 CNN forward 1회 추가 (~10% 학습 시간 증가)

 Training: GT position 기준 재생성 (batched: T_total×NA → 한번에 CNN)
 Blended:  blended state 기준 재생성 (step별)
 Inference: predicted state 기준 재생성 (step별)
```

## 5. Part B — Temporal Encoder & Latent Space

```
 ┌─────────────────────────────────────────────────────────────────────┐
 │              Temporal GCN Encoder (shared by Prior & Posterior)     │
 │                                                                    │
 │  Input: trajectory (NA, T, 6) + vis (NA, T) + lw + sem            │
 │                                                                    │
 │  Per-step processing:                                              │
 │    state(6) + lw(2) + vis(1) + sem(4) = 13                        │
 │    → MLP [13, 128, 64] = step_feature_extractor                   │
 │    → GCN (IndividualSceneInteractionNet)                           │
 │      in=64, NC=4, K=4, hidden=128, out=64                         │
 │    → gcn_feat (NA, 64)                                            │
 │                                                                    │
 │  Sequential: stack T steps → (NA, T, 64)                           │
 └─────────────────────────────────────────────────────────────────────┘

 ┌─────────────────────────────────────────────────────────────────────┐
 │ Prior Network (past only → z_global prior)                         │
 │                                                                    │
 │  (NA, PT=4, 64) → GRU (2-layer, 64→64) → last hidden (NA, 64)    │
 │  [past_context(64), map_feat(64), sem(4)] = 132                    │
 │  → MLP [132, 128, 64] → split → prior_μ(32), prior_logσ²(32)     │
 │                                                                    │
 │  Params: GRU=49,920 + MLP=25,536 = 75,456                        │
 │                                                                    │
 │  고뇌: GRU vs Transformer                                          │
 │    - Prior는 과거 4 step만 봄 → GRU로 충분 (경량)                   │
 │    - Transformer는 과거+미래 전체를 보는 posterior에만 사용          │
 │    - GRU의 recurrent inductive bias가 짧은 시퀀스에 유리            │
 └─────────────────────────────────────────────────────────────────────┘

 ┌─────────────────────────────────────────────────────────────────────┐
 │ Posterior Network (past + future → z_global posterior)              │
 │                                                                    │
 │  Past:   (NA, 4, 64) → GRU → past_context (NA, 64)                │
 │  Future: (NA, 12, 64) → PositionalEncoding                        │
 │          → TransformerEncoder (3 layers, d=64, 8 heads)            │
 │          → future_context = last token (NA, 64)                    │
 │                                                                    │
 │  [past_ctx(64), future_ctx(64), map_feat(64), sem(4)] = 196       │
 │  → MLP [196, 128, 64] → split → post_μ(32), post_logσ²(32)       │
 │                                                                    │
 │  Params: TF Encoder=843,456 + MLP=33,728 = 877,184                │
 │                                                                    │
 │  고뇌: Posterior에 Transformer를 쓴 이유                            │
 │    - 미래 12 step의 전체 trajectory를 보고 latent를 추출해야 함     │
 │    - 어떤 시점이 중요한지 attention으로 자동 선택                    │
 │    - GRU는 마지막 step에 편향, TF는 전체 균등 접근                   │
 └─────────────────────────────────────────────────────────────────────┘

 ┌─────────────────────────────────────────────────────────────────────┐
 │ Latent Space: z_global (32-dim)                                    │
 │                                                                    │
 │  역할: 미래 trajectory의 "모드"를 인코딩하는 global latent           │
 │    - 전체 경로의 대략적 방향/속도 패턴                               │
 │    - 상호작용 결과 (양보/추월/유지 등)                               │
 │                                                                    │
 │  VAE 구조:                                                          │
 │    Train: z ~ posterior (과거+미래 관측 후 인코딩)                   │
 │    Infer: z ~ prior (과거만으로 추정) 또는 z = prior_μ              │
 │    Loss:  KL(posterior || prior) → prior가 posterior를 모방하도록    │
 │                                                                    │
 │  고뇌: z_size=32 선택 (was 64 in earlier versions)                 │
 │    - 64-dim은 과도: 7,800 시나리오에 비해 latent 공간이 너무 넓음   │
 │    - 32-dim: 각 dim이 1-2개의 의미 있는 특성을 담도록 유도           │
 │    - AdaLN이 z를 매 layer에서 증폭하므로, 작은 z도 충분한 영향      │
 │                                                                    │
 │  z_global의 4가지 주입 경로 (V5):                                   │
 │    (1) Token construction: concat 후 projection (1회)              │
 │    (2) AdaLN: 매 layer 매 norm에서 gamma/beta 생성 (12회/forward)  │
 │    (3) A2Z cross-attn: z→4 tokens 분해, 매 layer cross-attention  │
 │    (4) z_aux: auxiliary decoder로 정보 보존 강제 (loss signal)      │
 └─────────────────────────────────────────────────────────────────────┘

 ┌───────────────────────────────────────┐
```

## 9. V5 변경사항 상세

### Change 1: AdaLN (Adaptive Layer Normalization)

```
 ┌─────────────────────────────────────────────────────────────────────┐
 │  기존 LayerNorm:  y = LN(x)                                        │
 │  AdaLN:           y = γ · LN(x) + β                                │
 │                   (γ, β) = MLP(z_global)                            │
 │                                                                    │
 │  MLP 구조: z(32) → Linear(32→128) → SiLU → Linear(128→256)        │
 │            → chunk(2) → γ(128), β(128)                              │
 │                                                                    │
 │  Identity Init:                                                    │
 │    - 마지막 Linear weight = 0, bias = [1,1,...1, 0,0,...0]          │
 │    - 초기: γ=1, β=0 → 순수 LayerNorm과 완전 동일                   │
 │    - 학습 진행: z_global의 정보가 점진적으로 γ, β를 조절             │
 │                                                                    │
 │  적용 위치 (per layer, 5개):                                        │
 │    a2t_norm, a2a_norm, a2s_norm, ego_ffn_norm, sur_ffn_norm        │
 │                                                                    │
 │  Params per norm: 37,504                                           │
 │  Total: 37,504 × 5 norms × 2 layers = 375,040                     │
 │                                                                    │
 │  z_global Broadcasting:                                            │
 │    A2T: z(N, 32) → (B*N, 1, 32) → broadcast over T                │
 │    A2A: z(N, 32) → (1, N, 32) → broadcast over B*T                │
 │    FFN: z(N_ego, 32) → (1, 1, N_ego, 32) → broadcast over B,T    │
 │                                                                    │
 │  근거: DiT (Diffusion Transformer) 논문에서 검증                    │
 │    - Conditioning signal이 매 layer에서 active하게 유지             │
 │    - FiLM conditioning의 Transformer 확장판                         │
 │    - Identity init으로 기존 모델과 backward-compatible              │
 │                                                                    │
 │  기대 효과:                                                         │
 │    - z_global이 4 layer 통과해도 희석되지 않음                       │
 │    - 각 layer에서 z 정보에 따라 feature를 능동적으로 조절             │
 │    - TensorBoard에서 adaln weight norm 추적 → z 활용도 확인          │
 └─────────────────────────────────────────────────────────────────────┘
```

### Change 4: z_global Auxiliary Decoder

```
 ┌─────────────────────────────────────────────────────────────────────┐
 │  목적: z_global이 trajectory 정보를 충분히 담고 있는지 검증 + 강제  │

 │  Params: 25,474                                                    │
 │    step_embed: 384                                                  │
 │    decoder: 25,090                                                  │
 │                                                                    │
 │  설계 고뇌:                                                         │
 │                                                                    │
 │  Q: 왜 MLP인가? Transformer가 더 잘 예측하지 않나?                  │
 │  A: 목적이 다름. "좋은 예측"이 아니라 "z_global의 정보량 probe."    │

 │                                                                    │

 │  A: (1) bicycle AR loop 불필요 → 연산 간단                          │
 │     (2) AR 오차 누적 없음 → 각 step 독립 gradient                   │
 │     (3) action ↔ position 수학적 동치 (bicycle은 결정론적 변환)     │
 │                                                                    │

 │     이 정보를 z에 압축하도록 강제하는 것이 목적.                     │
 │     inference 시 prior → z 근사는 KL loss가 담당.                   │
 └─────────────────────────────────────────────────────────────────────┘
```

### Change 6: Action Blending (TF→AR Bridge)

```
 ┌─────────────────────────────────────────────────────────────────────┐
 │  문제: Teacher Forcing은 GT state로 학습, AR는 자기 예측으로 추론   │
 │        → 학습/추론 분포 불일치 → AR 시 오차 누적 (exposure bias)    │
 │                                                                    │
 │  해결: Action Blending                                              │
 │    a_applied = (1 - α) · a_GT + α · â_predicted                    │
 │    s_{t+1} = BicycleModel(s_t, a_applied, veh_length)              │
 │                                                                    │
 │    α = 0: 순수 Teacher Forcing (초기 학습 안정성)                   │
 │    α = 1: 완전 Autoregressive (최종 목표)                            │
 │    0 < α < 1: GT와 예측의 action 내분 → 점진적 전환                 │
 │                                                                    │
 │  Annealing:                                                        │
 │    step < 10K:          α = 0 (순수 TF)                             │
 │    10K ≤ step < 75K:    α = linear ramp 0 → 1.0                    │
 │    step ≥ 75K:          α = 1.0 (완전 AR)                           │
 │                                                                    │
 │  핵심 설계 결정:                                                    │
 │                                                                    │
 │  ┌─ 왜 action-level blending인가? ─────────────────────────────┐   │
 │  │ State-level: s = (1-α)·s_GT + α·s_pred                      │   │
 │  │   → 물리적으로 inconsistent state 생성 가능                  │   │
 │  │   → bicycle model의 연속성 보장 깨짐                         │   │
 │  │                                                              │   │
 │  │ Action-level: a = (1-α)·a_GT + α·â_pred                     │   │
 │  │   → blended action을 bicycle model에 입력                    │   │
 │  │   → 물리적으로 valid한 state 항상 보장                        │   │
 │  │   → Scheduled Sampling의 action-level 변형                   │   │
 │  └──────────────────────────────────────────────────────────────┘   │
 │                                                                    │
 │  ┌─ Gradient 유지 ─────────────────────────────────────────────┐   │
 │  │ blended action → bicycle model → new state → GCN → token   │   │
 │  │ 전체 경로에서 detach 없음 → end-to-end gradient flow         │   │
 │  │ model이 "자기 예측 오차의 결과"를 학습할 수 있음              │   │
 │  └──────────────────────────────────────────────────────────────┘   │
 │                                                                    │
 │  ┌─ α=0 시작의 안전성 ─────────────────────────────────────────┐   │
 │  │ α=0이면:                                                     │   │
 │  │   a_applied = a_GT → bicycle(s_t, a_GT) → GT state 복원     │   │
 │  │   = 기존 Teacher Forcing과 수학적으로 완전 동일               │   │
 │  │   → 초기 학습은 안정적이고, 기존 코드와 호환                  │   │
 │  └──────────────────────────────────────────────────────────────┘   │
 │                                                                    │
 │  실행 흐름 (blended mode, α > 0):                                  │
 │                                                                    │
 │  Step 0: past(4 GT tokens) → Transformer → output_head → â₀       │
 │          a₀ = (1-α)·a_GT₀ + α·â₀                                  │
 │          s₁ = bicycle(last_past, a₀)   ← GT가 아닌 blended state   │
 │          s₁ → GCN → token_proj → new_token → append                │
 │                                                                    │
 │  Step 1: [past(4) + s₁] → Transformer → output_head → â₁          │
 │          a₁ = (1-α)·a_GT₁ + α·â₁                                  │
 │          s₂ = bicycle(s₁, a₁)                                      │
 │          ...                                                        │
 │                                                                    │
 │  Step 11: [past(4) + s₁..s₁₁] → Transformer → â₁₁ → bicycle → s₁₂│
 │                                                                    │
 │  z_global은 3경로로 지속 주입:                                      │
 │    (1) token_proj concat: 매 new token에 z 포함                    │
 │    (2) AdaLN: 매 layer 매 norm에서 modulation                       │
 │    (3) temporal PE: 독립적 (z와 무관하지만 positional 정보)          │
 │                                                                    │
 │  속도 vs TF:                                                        │
 │    TF: parallel forward (1번의 Transformer call)                    │
 │    Blended: sequential AR loop (FT번의 Transformer call)            │
 │    → 약 FT(12)배 느림. 초기 학습은 TF로 빠르게, 후반에 전환         │
 └─────────────────────────────────────────────────────────────────────┘
```

### Change 7: z_global Cross-Attention (A2Z)

```
 ┌─────────────────────────────────────────────────────────────────────┐
 │  문제: AdaLN은 modulation (γ,β)이지, z 정보의 직접 content 주입 아님│
 │        token construction concat은 layer 통과 시 희석 가능          │
 │        → z_global의 정보를 decoder가 "직접 참조"하는 경로 없음      │
 │                                                                    │
 │  해결: z_global → multi-token 분해 → cross-attention               │
 │    z_global(32) → Linear(32→512) → 4 tokens × 128                 │
 │    각 token = z_global의 한 측면 (자동 학습)                        │
 │                                                                    │
 │    K/V: z tokens에서 projection (shared)                           │
 │    Q/O: ego/sur 별도 projection (역할별 query 분리)                 │
 │    → A2A와 A2S 사이에 삽입 (매 layer)                               │
 │                                                                    │
 │  Params per layer: 153,472                                          │
 │    AdaLN norm:     37,504                                           │
 │    z_token_proj:   16,896 (32→512)                                 │
 │    K/V proj:       32,896 (128→128 × 2)                            │
 │    ego Q/O:        32,896 (128→128 × 2)                            │
 │    sur Q/O:        32,896 (128→128 × 2)                            │
 │  Total: 153,472 × 2 layers = 306,944                              │
 │                                                                    │
 │  설계 고뇌:                                                         │
 │                                                                    │
 │  Q: AdaLN과 중복 아닌가?                                            │
 │  A: 상호 보완적. AdaLN = "feature를 어떻게 변환할지" (modulation),  │
 │     A2Z = "z에서 무슨 정보를 가져올지" (content attention).          │
 │     AdaLN은 모든 agent에 동일한 변환, A2Z는 agent별 다른 정보 추출. │
 │                                                                    │
 │  Q: 왜 4 tokens?                                                    │
 │  A: z_global 32dim을 여러 측면으로 분해 (속도 프로파일, 방향,       │
 │     상호작용 패턴, 안전 마진 등). 1 token이면 bottleneck,           │
 │     너무 많으면 over-parameterization. 4는 경험적 선택.             │
 │                                                                    │
 │  Q: decoder가 z를 무시할 수 없나?                                   │
 │  A: cross-attention은 직접 참조 → concat 후 희석되는 것과 다름.     │
 │     z tokens의 V 값이 직접 output에 더해짐.                        │
 │     + AdaLN + z_aux loss와 삼중으로 z 활용 강제.                    │
 └─────────────────────────────────────────────────────────────────────┘
```

### Change 8: recon_pos_weight (Position Gradient Boost)

```
 ┌─────────────────────────────────────────────────────────────────────┐
 │  문제: Position (x,y) 정규화 std=15, heading (hx,hy) [-1,1]       │
 │        log_normal에서 position gradient ≈ MSE/2 = (err/15)²/2     │
 │        heading gradient ≈ (err)²/2                                  │
 │        → 동일 "실제 오차"에서 position gradient가 ~225배 약함       │
 │                                                                    │
 │  해결: L_recon = log_normal(4dim) + recon_pos_weight × pos_mse     │
 │        weight=10: position MSE에 추가 gradient 부여                 │
 │                                                                    │
 │  구현:                                                              │
 │    recon_loss = -log_normal(pred_4d, GT_4d, I)                      │
 │    pos_mse = Σ(pred_xy - GT_xy)²                                   │
 │    if recon_pos_weight > 0:                                         │
 │        recon_loss += recon_pos_weight * pos_mse                     │
 │                                                                    │
 │  Monitoring:                                                        │
 │    pos_loss = pos_mse = Σ(pred_xy - GT_xy)²      ← TensorBoard    │
 │    head_loss = head_mse = Σ(pred_hxhy - GT_hxhy)²                  │
 │    (기존 log_normal → MSE로 변경: 실제 학습 loss와 일치하도록)      │
 │                                                                    │
 │  고뇌:                                                              │
 │                                                                    │
 │  Q: log_normal variance 조절이 더 깔끔하지 않나?                    │
 │  A: variance<1이면 -log(√v) 상수항이 음수 → loss 자체가 줄어듦.    │
 │     실험: weight=20(v=1/20) → recon=0.7 (기존 3.7). 수치 혼란.     │
 │                                                                    │
 │  Q: 순수 weighted MSE로 하면?                                       │
 │  A: log_normal 상수항(3.68) 제거 → loss 스케일 완전 변경.           │
 │     다른 loss weight(kl, aux)와 호환 깨짐. 실험: train 0.08 vs val 40.│
 │                                                                    │
 │  Q: weight=10은 적절한가? 자전거 모델에서.                          │
 │  A: 30km/h에서 heading 5° → 0.36m/step lateral drift.              │
 │     Position 1m > heading 5°의 실제 영향. weight=10은              │
 │     position gradient를 heading의 ~10배로 → position 우선 학습.     │
 │     자전거 모델이므로 position이 맞으면 heading도 따라옴.            │
 └─────────────────────────────────────────────────────────────────────┘
```

## 10. Loss 구성

```
 ┌─────────────────────────────────────────────────────────────────────┐
 │  Total Loss = L_recon + L_kl + L_aux + L_potential                 │
 └─────────────────────────────────────────────────────────────────────┘

 ┌─────────────────────────────────────────────────────────────────────┐
 │ (1) Reconstruction Loss — L_recon (weight: 1.0)                    │
 │                                                                    │
 │  L_recon = -log N(pred | GT, I) + recon_pos_weight × pos_mse      │
 │                                                                    │
 │  기본: -log N = 0.5 * ||pred - GT||² + const (4 dims)             │
 │  추가: recon_pos_weight(10) × Σ(pred_xy - GT_xy)²                 │
 │                                                                    │
 │  pred: (NA, FT, 4) = (x, y, hx, hy) normalized                   │
 │  GT:   (NA, FT, 4) = future_gt[:, :, :4]                          │
 │  모든 agent (ego + sur), visibility mask 적용                       │
 │                                                                    │
 │  Monitoring (TensorBoard):                                         │
 │    pos_loss: pos_mse = Σ(pred_xy - GT_xy)²  (MSE 스케일)          │
 │    head_loss: head_mse = Σ(pred_hxhy - GT_hxhy)²                  │
 │    (실제 학습에 기여하는 MSE와 동일한 스케일로 표시)                │
 │                                                                    │
 │  고뇌: recon_pos_weight 설계                                       │
 │    - Position은 std=15로 정규화, heading은 [-1,1] unit vector      │
 │    - log_normal에서 position gradient가 heading 대비 약함           │
 │    - 자전거 모델: 1m position error > 5° heading error (30km/h)    │
 │    - weight=10: position gradient를 ~10× 강화                      │
 │    - log_normal에 MSE 직접 더하기: 기존 loss 스케일 유지 + 독립     │
 │      gradient control. 상수항 증폭 없음                             │
 │                                                                    │
 │  역할: 주 학습 signal. trajectory 품질의 직접 지표.                  │
 ├─────────────────────────────────────────────────────────────────────┤
 │ (2) KL Divergence Loss — L_kl (weight: 0.004, annealing)           │
 │                                                                    │
 │  KL(q(z|past,future) || p(z|past))                                 │
 │  per-agent, per-dim KL → mean                                      │
 │  Annealing: 0 → 0.004 over epoch 0~30 (linear ramp)               │
 │  Phase 1 only (Phase 2에서는 z_global frozen)                       │
 │                                                                    │
 │  역할: posterior를 prior에 근사시킴                                  │
 │  고뇌:                                                              │
 │    - weight 0.004: β-VAE에서 β < 1 → reconstruction 우선            │
 │    - 너무 크면 posterior collapse (z → prior로 수렴)                 │
 │    - 너무 작면 prior가 posterior를 못 따라감 → 추론 시 z 품질 저하   │
 │    - KL oscillation은 건강한 신호: z가 실제 정보를 인코딩 중         │
 ├─────────────────────────────────────────────────────────────────────┤
 │ (3) Auxiliary Losses — L_aux                                       │
 │                                                                    │
 │  (A) Sur Pred Loss (weight: 0.1)                                   │
 │      ego A2A output → Linear(128→2) → predicted sur delta          │
 │      vs GT sur position delta                                       │
 │      MSE per step, averaged                                         │
 │      역할: ego가 sur의 움직임을 인지하도록 강제                      │
 │                                                                    │
 │  (B) Ego Pred Loss (weight: 0.1)                                   │
 │      sur A2A output → Linear(128→2) → predicted ego delta          │
 │      vs GT ego position delta                                       │
 │      역할: sur가 ego의 움직임을 인지하도록 강제                      │
 │                                                                    │
 │  (C) Intent CE Loss (weight: 0.05)                                 │
 │      z_local → Linear(32→9) → logits                               │
 │      GT: (acc, yaw) → 9 prototypes → Gaussian soft label            │
 │      KL(soft_label || softmax(logits))                              │
 │      역할: intent codebook이 의미 있는 행동을 인코딩하도록 유도     │
 │                                                                    │
 │  (D) Map Attn Guidance Loss (weight: 0.05, annealing)              │
 │      Layer 0 A2S attention weights vs GT trajectory soft label      │
 │      Soft label: trajectory polyline 기반 (RF 좌표 매핑 사용)       │
 │        - 종방향: exponential decay along arc length                 │
 │        - 횡방향: Gaussian band (σ_d=0.8 grid cells ≈ 2.1m)        │
 │        - 좌표: _m2token_l/w() — RF center 기반 정확한 매핑          │
 │      KL(soft_label || attn_weights) per step, averaged              │
 │      ego + sur 모두 적용                                            │
 │                                                                    │
 │      Full lookahead 제한: max_t = FT - map_gt_steps                │
 │        t=0~5만 loss 계산 (remaining=6 고정, full lookahead)         │
 │        t=6~11: loss 없음, attention은 정상 동작                      │
 │        이유: GT 부족한 후반 step의 짧은 soft label이                 │
 │              "좁게 봐라" gradient → 초반 "넓게" gradient와 상충      │
 │        A2S weight 공유이므로 초반 학습 패턴이 후반에도 유지           │
 │                                                                    │
 │      Drivable potential weighting:                                  │

 │      역할: 초기 학습에서 map attention이 올바른 도로에 집중하도록    │
 │            → 수렴 후 자유롭게 학습하도록 guidance 제거               │
 │                                                                    │
 │  (E) z_aux Loss (weight: 0.1)                                      │
 │      z_aux_decoder output vs GT actions                             │
 │      MSE(z_aux_pred, gt_actions)                                    │
 │      역할: z_global이 trajectory 정보를 충분히 담도록 강제           │
 │      Train + Val 모두 실행                                          │
 ├─────────────────────────────────────────────────────────────────────┤
 │ (4) Potential Loss — L_potential                                    │
 │                                                                    │
 │  Env Potential (weight: 0.1):                                      │
 │    ego → non-drivable area 경계와의 거리 → exponential repulsion   │
 │    U(d) = k · exp(-d/σ)                                             │
 │    k_boundary=1.0, σ_boundary=0.5                                   │

 │                                                                    │
 │  Veh Potential (weight: 0.0, disabled):                             │
 │    ego → 다른 agent와의 거리 기반 반발력                             │

 └─────────────────────────────────────────────────────────────────────┘

 ┌─────────────────────────────────────────────────────────────────────┐
 │  Loss Weight Summary                                               │
 │                                                                    │
 │  ┌──────────────────┬──────────┬───────────────────────────────┐   │
 │  │ Loss             │ Weight   │ Annealing                     │   │

 │  │ recon            │ 1.0      │ -                             │   │
 │  │ recon_pos_weight │ 10       │ - (recon 내부, pos MSE 가중)  │   │
```

## 15. Rollback 안전장치

```
 모든 V5 feature의 기본값 = V4 동작 (no-op):

 ┌─────────────────────────┬───────────────┬──────────────────────┐
 │ Feature                 │ Default (V4)  │ V5 Active            │
 ├─────────────────────────┼───────────────┼──────────────────────┤
 │ use_adaln               │ False         │ True                 │
 │ use_a2a_rel_bias        │ False         │ True                 │
 │ use_z_cross_attn        │ False         │ True                 │
 │ trans_num_layers        │ 4             │ 2                    │
 │ trans_ffn_dim           │ 512           │ 256                  │
 │ loss_z_aux              │ 0.0           │ 0.1                  │
 │ recon_pos_weight        │ 1.0 (=off)    │ 10                   │
 │ action_blending         │ False         │ True                 │
 │ map_recrop              │ False         │ True                 │
 └─────────────────────────┴───────────────┴──────────────────────┘

 안전 메커니즘:
   AdaLN      → identity init (γ=1, β=0): 초기 = 기존 LN
   A2A Bias   → zero init: 초기 bias=0 → 기존 attention
   A2Z Attn   → config off 가능, use_z_cross_attn=False
   z_aux      → weight 0.1: gradient signal만, 학습 지배 안 함
   Blending   → α=0 start: 초기 = 순수 Teacher Forcing
   recon_pos  → weight=0이면 기존 log_normal과 동일
```
